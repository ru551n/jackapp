# Platform decisions (deployment and runtime)

| Topic            | Choice                                                                                   | Why                                                                                                                                                                                                                      |
| ---------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Server build     | esbuild bundle (`scripts/build-server.mjs`) into `dist-server/`, ESM, code splitting     | esbuild is already installed (tsx and drizzle-kit use it); one call, ~100 ms. Bundling all dependencies means the runtime image has **no `node_modules`**, so web-only dependencies (React, onnxruntime-web) never ship. |
| Not tsup / tsc   | —                                                                                        | tsup is a wrapper around the same esbuild (an extra dependency). `tsc` output would need `node_modules` at runtime and path rewriting for `.ts` imports.                                                                 |
| Entrypoints      | `main.js` (app), `worker.js`, `migrate.js`, `worker-health.js`                           | One image, different commands.                                                                                                                                                                                           |
| Migrations       | drizzle-kit SQL files in `server/db/migrations`, applied by a one-shot `migrate` service | App and worker never race on schema changes. A Postgres advisory lock serializes concurrent migrate runs anyway.                                                                                                         |
| Readiness        | `database` (`select 1`) and `migrations` (no journal entry newer than the last applied)  | Same rule drizzle's migrator uses to decide what is pending.                                                                                                                                                             |
| Worker health    | Heartbeat file `/data/worker-heartbeat-<hostname>`, checked by `worker-health.js`        | No extra port or table. Proves the process is alive; the job runtime may call `beat()` to tie it to job progress.                                                                                                        |
| Runtime image    | `node:22-bookworm-slim` + `poppler-utils` + `tini`, user `node`                          | glibc base for poppler; tini forwards SIGTERM so graceful shutdown works.                                                                                                                                                |
| Published port   | `127.0.0.1:3000` only                                                                    | The app has no login. Anything that can reach port 3000 bypasses the proxy's access control.                                                                                                                             |
| Networks         | `backend` (internal, db) + `egress` (app/worker outbound, published port)                | The database has no route to or from the outside.                                                                                                                                                                        |
| Empty env values | `KEY=` is treated as unset                                                               | `.env.example` lists every variable; blanks fall back to defaults instead of failing validation.                                                                                                                         |
